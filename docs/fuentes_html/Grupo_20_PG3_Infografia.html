¿Cómo funciona? (patrón sándwich)

📝 Aviso o consulta→ 🧭 LLM enrutador (System Prompt maestro)→ 🔎 LLM extrae JSON→ ✅ Validación contra el texto→ 🧠 Neo4j: reglas + difusa + componentes→ 💬 LLM explica (con control anti-alucinación)

🛠️ SM1 · Diagnóstico técnico

  • Falla insalvable → inviable (R1.1)
  • Batería y temperatura con lógica difusa Mamdani
  • Plan: RAM, SSD, pantalla, teclado, cargador, mano de obra
  • Costos desde CostoReparacion

📊 SM2 · Valuación por componentes

  • Valor del procesador × factor de línea × factor de RAM
  • Calibrado con medianas de avisos reales
  • ThinkPad ×1,08 · Latitude ×0,72 · Gamer ×1,7
  • Riesgo de obsolescencia y demanda (difusa)

⚖️ SM3 · Decisión

  • R3.7 reparación > 50 % del VMA → descartar
  • R3.8 riesgo Alto + demanda Baja → descartar
  • Margen requerido: base → R3.4 / R3.5 → R3.6
  • Conveniencia difusa → contraoferta en pesos

🧾 Trazabilidad

  • Cada número sale de un nodo con fuente, versión y estado
  • Decisión Firme o Provisional
  • Falta un dato → pendiente; no está en el grafo → error
  • Reglas activadas visibles en la interfaz
